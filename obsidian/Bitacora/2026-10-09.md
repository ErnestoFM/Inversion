# Bitácora de Trabajo — 2026-10-09

## 📌 Resumen de la Sesión
En esta sesión se resolvió el incidente de fallo en el despliegue a **Google Cloud Run** del servicio backend `sigre-api` en el pipeline CI/CD de GitHub Actions (`The user-provided container failed to start and listen on the port defined provided by the PORT=8080 environment variable within the allocated timeout`).

Tras analizar los registros de arranque del contenedor en Cloud Logging, se detectó que Node.js 20 fallaba en el contenedor de producción con `SyntaxError: Unexpected identifier 'global'` debido a que el paquete interno `@inversion/database` exportaba directamente código TypeScript en su `main` (`./src/index.ts`) sin haber sido compilado a JavaScript (`dist/index.js`), provocando la caída inmediata del proceso al interpretar la declaración `declare global { ... }`.

Se reconfiguró el paquete `@inversion/database` con TypeScript compilado a `dist/`, se agregaron las definiciones `@types/node`, se actualizó el Dockerfile de la API para compilar la base de datos previo a la imagen final, y se configuró `server.ts` para enlazar explícitamente en el host `0.0.0.0:${PORT}` cumpliendo con las directivas de Cloud Run.

## 🔍 Detalles Técnicos y Diagnóstico de Causa Raíz
- **Causa Raíz:** En entornos de desarrollo y pruebas, `tsx` interpreta TypeScript en memoria al vuelo. Sin embargo, en el contenedor Docker de producción de `apps/api`, la imagen ejecuta Node.js nativo (`node dist/server.js`). Al importar `@inversion/database`, Node resolvía el campo `main` que apuntaba a `./src/index.ts`. Al leer la sintaxis TypeScript pura `declare global`, Node arrojaba `SyntaxError: Unexpected identifier 'global'` y abortaba la ejecución (`exit(1)`).
- **Falla del Probe de Cloud Run:** Dado que el proceso de Node moría antes de iniciar el listener de Express, el TCP probe de Cloud Run en el puerto `8080` no recibía respuesta y cancelaba la revisión tras alcanzar el tiempo de espera.
- **Resolución:**
  1. Compilación de `@inversion/database` a CommonJS estándar en `packages/database/dist/index.js`.
  2. Inclusión del paso de build en el Dockerfile multi-stage.
  3. Enlace estricto en la interfaz de red `0.0.0.0`.
